## 1.1 Jaccard 유사도 지수 (태그 집합 유사도)

### 산출 방법론

Jaccard 유사도 지수는 두 집합 A, B의 교집합 크기를 합집합 크기로 나눈 값입니다:

```
J(A, B) = |A ∩ B| / |A ∪ B|
```

3주체 Jaccard는 다음과 같이 확장합니다:

```
J(A, B, C) = |A ∩ B ∩ C| / |A ∪ B ∪ C|
```

### 3주체 정의

| 주체 | 약칭 | 정의 | 태그/항목 수 |
|------|------|------|:----------:|
| **Column 1: PLC 공급** | P | 현업 확인 47개 PLC 태그 — 설비에 물리적으로 존재하는 데이터 | 47 |
| **Column 2: 현업 수요** | O | 설문조사 12개 항목 — 현업이 품질에 중요하다고 판단하는 항목 | 12 |
| **Column 3: AI 실행** | A | 10개 카테고리 ~93개 태그 — AI가 실제 모니터링 중인 태그 | ~93 |

### 구간별 항목 집합 및 Jaccard 산출

**분석 단위**: 각 구간에서 3주체가 언급/활용하는 **측정 개념(concept)**을 기준으로 합니다.

#### 가열로 구간

| 측정 개념 | P (PLC) | O (현업) | A (AI) |
|----------|:-------:|:-------:|:------:|
| 추출 온도 | 1 | 1 | 1 |
| 체류시간 | 0 | 1 | 0 |
| 상부 존 온도 | 0 | 0 | 1 |
| 하부 존 온도 | 0 | 0 | 1 |
| 부대설비(O2, 압력, 가스) | 0 | 0 | 1 |

- P = {추출온도}, O = {추출온도, 체류시간}, A = {추출온도, 상부온도, 하부온도, 부대설비}
- J(P,O) = |{추출온도}| / |{추출온도, 체류시간}| = 1/2 = **0.50**
- J(P,A) = |{추출온도}| / |{추출온도, 상부, 하부, 부대}| = 1/4 = **0.25**
- J(O,A) = |{추출온도}| / |{추출온도, 체류, 상부, 하부, 부대}| = 1/5 = **0.20**
- J(P,O,A) = |{추출온도}| / |{추출온도, 체류, 상부, 하부, 부대}| = 1/5 = **0.20**

#### 스탠드 구간

| 측정 개념 | P (PLC) | O (현업) | A (AI) |
|----------|:-------:|:-------:|:------:|
| Stand 토크 | 0* | 1 | 1 |
| Stand 속도 | 1 | 0 | 1 |
| Stand 부하 | 0 | 0 | 1 |

> *PLC 47개 목록에는 Stand14 속도만 포함. Stand 토크는 DB에 존재하나 현업 확인 47개 PLC 태그 외 범위.
> 단, AI가 Stand 토크를 분석 중이고, 현업이 Stand 1/2/14 토크를 요청했으므로 개념 수준에서는 3주체 합의.

- 개념 수준 보정: Stand 토크는 DB에 존재하므로 P에도 포함
- P = {토크, 속도}, O = {토크}, A = {토크, 속도, 부하}
- J(P,O) = |{토크}| / |{토크, 속도}| = 1/2 = **0.50**
- J(P,A) = |{토크, 속도}| / |{토크, 속도, 부하}| = 2/3 = **0.67**
- J(O,A) = |{토크}| / |{토크, 속도, 부하}| = 1/3 = **0.33**
- J(P,O,A) = |{토크}| / |{토크, 속도, 부하}| = 1/3 = **0.33**

#### PR3/4 구간

- P = {속도, 토크, 기준속도}, O = {토크}, A = {속도, 토크, 기준속도, 기준토크}
- J(P,O) = |{토크}| / |{속도, 토크, 기준속도}| = 1/3 = **0.33**

## 1.2 Fleiss' Kappa (평가자 간 일치도)

### 산출 방법론

Fleiss' Kappa는 3명 이상의 평가자가 같은 대상을 범주형으로 평가할 때 일치도를 측정합니다:

```
κ = (P_obs - P_exp) / (1 - P_exp)
```

여기서:
- P_obs = 관찰된 일치도 (실제 일치 비율)
- P_exp = 우연 일치도 (랜덤 배정 시 기대 일치 비율)

#### Fleiss' Kappa 계산

평가자 수 n = 3, 항목 수 N = 47, 범주 수 k = 2 (중요/비중요)

**각 항목 i에 대해 일치도 P_i 계산:**

```
P_i = (1/(n(n-1))) * Σ(n_ij^2 - n)
    = (1/(3*2)) * Σ(n_ij^2 - 3)
    = (1/6) * (n_1^2 + n_0^2 - 3)
```

| 패턴 | n_1 (=1 수) | n_0 (=0 수) | P_i |
|:----:|:----------:|:----------:|:---:|
| (1,1,1) | 3 | 0 | (9+0-3)/6 = 1.00 |
| (1,1,0) | 2 | 1 | (4+1-3)/6 = 0.33 |
| (1,0,1) | 2 | 1 | (4+1-3)/6 = 0.33 |
| (1,0,0) | 1 | 2 | (1+4-3)/6 = 0.33 |

**관찰 일치도 P_obs:**

```
P_obs = (1/N) * Σ P_i
      = (1/47) * [9*1.00 + 14*0.33 + 14*0.33 + 10*0.33]
      = (1/47) * [9.00 + 4.62 + 4.62 + 3.30]
      = (1/47) * 21.54
      = 0.458
```

**기대 일치도 P_exp:**

전체 "1" 비율: p_1 = (9*3 + 14*2 + 14*2 + 10*1) / (47*3) = (27+28+28+10)/141 = 93/141 = 0.660
전체 "0" 비율: p_0 = 1 - 0.660 = 0.340

```
P_exp = p_1^2 + p_0^2 = 0.660^2 + 0.340^2 = 0.436 + 0.116 = 0.551
```

**Fleiss' Kappa:**

```
κ = (P_obs - P_exp) / (1 - P_exp)
  = (0.458 - 0.551) / (1 - 0.551)
  = -0.093 / 0.449
  = -0.207
```

## 1.3 Spearman 순위 상관 (ρ)

### 산출 방법론

현업 설문 순위와 AI 이상 점수(total_score) 순위 간의 상관을 측정합니다:

```
ρ = 1 - (6 * Σd_i^2) / (n * (n^2 - 1))
```

| PR Torque (PR3) | 3 | 3 (46.66) | 0 | 0 |
| PR Torque (PR4) | 4 | 4 (42.66) | 0 | 0 |
| Stand 2 토크 | 5 | 5 (35.88) | 0 | 0 |
| 추출 온도 | 6 | 6 (30.00) | 0 | 0 |

> 현업 순위 재정규화: 겹치는 항목만 추출 후 1~6 재배정. 현업 원래 순위에서 Stand 토크(#10~12)는 3위 그룹이지만 AI 점수에서는 최상위이므로, 현업 순위를 설문 순서대로 재정규화.

정확한 비교를 위해 원래 설문 순위를 보존합니다:

| 항목 | 현업 원 순위 | AI 점수 순위 (6개 중) | d | d^2 |
|------|:----------:|:------------------:|:-:|:---:|
| 추출 온도 | 1 | 6 (30.00점, 최하) | -5 | 25 |
| PR Torque (PR3) | 3 → 2 | 3 (46.66) | -1 | 1 |
| PR Torque (PR4) | 3 → 3 | 4 (42.66) | -1 | 1 |
| Stand 14/10 토크 | 10 → 4 | 1 (69.00) | 3 | 9 |
| Stand 1 토크 | 11 → 5 | 2 (48.97) | 3 | 9 |
| Stand 2 토크 | 12 → 6 | 5 (35.88) | 1 | 1 |

> 설문 순위 정규화: 매핑 가능한 6개 항목만 추출하여 순위 1~6으로 재배정 (원 순위 순서 보존)

**Spearman ρ 계산:**

```
Σd^2 = 25 + 1 + 1 + 9 + 9 + 1 = 46
n = 6

ρ = 1 - (6 * 46) / (6 * (36 - 1))
  = 1 - 276 / 210
  = 1 - 1.314
  = -0.314
```

### 결과 해석

```
Spearman ρ = -0.314 (약한 음의 상관)

해석:
- 현업이 1순위로 꼽은 "추출 온도"는 AI 이상 점수에서 최하위 (30.00점)
- 현업이 하위에 둔 "Stand 토크"는 AI 이상 점수에서 최상위 (69.00점)
- 이 역전 현상이 음의 상관을 만듦
```

![Spearman 순위 산점도](charts/S1_07_spearman_scatter.png)


**역전 원인 분석:**

| 현상 | 원인 |
|------|------|
| 추출 온도가 AI에서 낮은 점수 | 추출 온도는 안정적으로 관리되어 이상 탐지 빈도가 낮음 (= 잘 관리되고 있음) |
| Stand 토크가 AI에서 높은 점수 | Stand 토크는 변동성이 크고 이상 패턴이 빈번하여 AI가 높은 점수 부여 |

> **핵심 통찰**: AI 이상 점수가 높다 = 문제가 많다는 뜻이므로, **현업이 중요하다고 판단하는 항목과 AI가 이상을 감지하는 항목은 다른 차원**의 개념입니다. 현업은 "품질에 중요한 것"을, AI는 "통계적으로 비정상인 것"을 보고 있습니다.

> **고객 설명 포인트**: "음의 상관(-0.31)은 나쁜 것이 아닙니다. 현업이 1순위로 꼽은 추출 온도가 AI에서 점수가 낮다는 것은, 추출 온도가 현재 잘 관리되고 있어서 이상이 적다는 긍정적 신호입니다. 반대로 Stand 토크의 AI 점수가 높다는 것은 해당 영역에서 미세한 이상 패턴이 감지되고 있으니 주의가 필요하다는 의미입니다."

## 2.2 Process FMEA (공정 고장 모드 및 영향 분석)

> **고객 설명 포인트**: "각 공정 구간이 고장나면 얼마나 심각한지(S), 얼마나 자주 발생하는지(O), 현재 얼마나 잘 감지하는지(D)를 점수화하여 위험도(RPN)를 산출합니다. RPN이 높을수록 우선 개선 대상입니다."

### RPN 산출 기준

| 요소 | 약어 | 범위 | 판정 근거 |
|------|:----:|:----:|-----------|
| 심각도 (Severity) | S | 1-10 | 해당 구간 고장 시 최종 코일 품질 영향도 |
| 발생도 (Occurrence) | O | 1-10 | AI 분석 이상치 빈도 기반 (미분석 구간은 "?" 표시) |
| 검출도 (Detection) | D | 1-10 | 현재 AI 모니터링 역량 (1=잘 감지, 10=감지 불가) |
| **RPN** | | 1-1000 | S x O x D (높을수록 위험) |

### FMEA 매트릭스

| 공정 구간 | 주요 고장 모드 | S | O | D | **RPN** | 등급 | 해석 |
|----------|--------------|:-:|:-:|:-:|:-------:|:----:|------|
| **VCC** | 권취 속도/루프 이상 -> 코일 형상 불량 | 9 | ? | 10 | **>=810** | !! | **감지 불가**: PLC 미수집, AI 미분석. 현업 핵심 관심 영역 |
| **Water Box** | 냉각 이상 -> 재질/형상 불량 | 8 | ? | 10 | **>=720** | !! | **감지 불가**: PLC 미수집, AI 미분석. 현업 3개 항목 요청 |
| **DST** | 충전 패턴 이상 -> 코일 형상 불균일 | 7 | ? | 10 | **>=630** | !! | **감지 불가**: PLC 미수집, AI 미분석 |
| **PR6~9** | 토크/속도 이상 -> 형상 직접 영향 | 8 | 5 | 3 | **120** | ! | AI 분석 중이나 L2 일부 누락 |
| **PR3/4** | 속도/토크 이탈 -> 형상 불량 | 7 | 4 | 2 | **56** | | AI 6기법 적용, 잘 커버됨 |
| **가열로** | 추출 온도 이탈 -> 재질 불량 | 7 | 4 | 2 | **56** | | AI 6기법 적용, 골든 존 |
| **스탠드** | 토크 이상 -> 치수 불량 | 6 | 4 | 2 | **48** | | AI 46태그 분석, 충분한 커버리지 |
| **PR005** | 보조 PR 이탈 -> 형상 영향 중간 | 5 | ? | 10 | **>=450** | !! | **감지 불가**: PLC 미수집, 현업 미요청 |

> **O(발생도) "?" 처리**: Water Box, VCC, DST, PR005는 AI 분석 데이터가 없어 이상 발생 빈도 추정이 불가합니다. 최소 발생도를 9(추정)로 가정하면 RPN은 위 표의 ">=" 값이 됩니다.

> **[데이터 한계 주의 -- FMEA O(발생도)가 "?"인 근본 원인]**
>
> FMEA에서 O(발생도)를 정량화하지 못하는 이유는 단순히 "PLC 미수집" 때문만이 아닙니다. **결함 데이터 자체에 7가지 구조적 한계(L1~L7)**가 존재합니다:
>
> | 한계 ID | 내용 | 심각도 | FMEA 영향 |
> |:-------:|------|:------:|----------|
> | **L1** | 시간 해상도 불일치: 불량=일별 집계, IBA=초 단위 | ★★★★★ | 어떤 코일에서 불량인지 특정 불가 -> O 산출 불가 |
> | **L2** | 강종 코드 불일치: defect DB의 SD400/SD500 vs IBA의 D4/D5 | ★★★★ | 강종별 발생 빈도 산출 불가 |
> | **L3** | 번들-코일 연결 부재: 번들 완료 시점과 IBA 코일 구간 매핑 미구현 | ★★★★ | 개별 코일의 불량 여부 판정 불가 |
> | **L5** | 소량 데이터: 6개월, 강종별 5~30일 | ★★★★ | 통계적으로 의미 있는 빈도 추정 곤란 |
> | **L7** | 불량률=0 날 다수: 극도의 클래스 불균형 | ★★★ | 발생도 추정의 신뢰구간이 넓음 |
>
> **대안 접근 (Anomaly-First, B1)**: 결함 데이터 없이도 기존 6기법(IQR, Adj-IQR, CUSUM-EWMA, STL, Rolling-Z, Mahalanobis) 이상치 탐지 결과를 활용하여 O를 우회적으로 추정할 수 있습니다. 이상치 빈도가 높은 공정 구간 = 발생도가 높은 구간으로 간주하는 접근법입니다. 현재 분석 중인 골든 존(가열로, 스탠드, PR3/4)에서는 이 방법으로 O=4를 산출했습니다.

> **[데이터 한계 주의]** FTA는 "어떤 사건 조합이 불량으로 이어지는가"를 분석하는 기법이나, 현재 **L1(시간 불일치)**으로 인해 "실제 불량 코일에서 어떤 기본 사건이 발생했는가"를 데이터로 검증할 수 없습니다. 다시 말해, 고장수의 **구조(어떤 원인이 존재하는가)**는 도메인 지식으로 정의할 수 있지만, **확률(각 원인이 얼마나 기여하는가)**은 코일 단위 추적 데이터 없이는 산출이 불가합니다. **대안**: C4(불량일 vs 정상일 프로파일 비교)와 C3(변화점 빈도-불량률 상관) 분석을 통해, FTA 경로 D(상류 이상)에 대해서는 일별 수준에서의 우회적 검증이 가능합니다.

## 2.5 데이터 한계와 인과 분석의 현실적 제약

### 2.5.3 대응 전략: Anomaly-First 접근

결함 데이터의 한계를 인정한 위에서, **결함 라벨 없이도 공정-품질 연결을 확보**할 수 있는 3단계 대응 전략을 수립했습니다.

#### 전략 B1: Anomaly-First (이상치 우선) 접근 -- 기존 인프라 95% 재활용

```
기존 접근 (데이터 의존):                Anomaly-First 접근 (라벨 불요):
┌─────────────┐                      ┌─────────────┐
│ 불량 데이터   │ ─── L1~L7 차단 ──→  │ IBA 시계열    │
│ (일별 집계)   │      ╳              │ (초 단위)     │
└──────┬──────┘                      └──────┬──────┘
       │                                    │
       ▼                                    ▼
  불량 코일 특정  ← 불가             6기법 이상치 탐지  ← 가능
       │                            (IQR, CUSUM, STL,
       ▼                             Mahalanobis, ...)
  인과 분석     ← 불가                     │
                                           ▼
                                    이상치 빈도 집계  ← 가능
                                           │
                                           ▼
                                    불량일 vs 정상일   ← 가능
                                    프로파일 비교
                                           │
                                           ▼
                                    공정-품질 연결    ← 우회 확보!
```

**핵심 아이디어**: 결함 데이터(413건, 일별)에 의존하지 않고, IBA 시계열(939K건, 초 단위)에 이미 적용된 **6가지 이상치 탐지 기법**의 결과를 직접 활용합니다. 이상치가 빈번한 구간 = 품질 위험이 높은 구간으로 판정하는 접근법입니다.

| 항목 | 기존 접근 | Anomaly-First |
|------|:--------:|:------------:|
| 필요 데이터 | 코일 단위 불량 라벨 | IBA 시계열만 (보유 중) |
| 데이터 한계 영향 | L1~L7 전면 차단 | L1~L7 우회 가능 |
| 기존 인프라 활용 | 0% | **95%** (6기법 결과 100% 재활용) |
| 추가 개발 | 코일 추적 시스템 필요 | 최소 (교차 검증 코드만) |
| 분석 수준 | 코일 단위 정밀 분석 | 일별/구간별 패턴 분석 |

#### 전략 C4: 불량일 vs 정상일 프로파일 비교

일별 집계 수준(L1의 한계 범위 내)에서 가능한 최선의 검증 방법입니다.

```
불량 발생일 (30일)                     정상일 (97일)
┌──────────────┐                    ┌──────────────┐
│ IBA 태그별     │                    │ IBA 태그별     │
│ 일별 통계      │                    │ 일별 통계      │
│ (평균, 분산,   │                    │ (평균, 분산,   │
│  왜도, 첨도)   │                    │  왜도, 첨도)   │
└──────┬───────┘                    └──────┬───────┘
       │                                   │
       └──────────┬────────────────────────┘
                  ▼
         Mann-Whitney U 검정
         KS test (분포 차이)
         Cohen's d (효과 크기)
                  │
                  ▼
         "불량일에 유의하게 다른 태그 Top-20"
         → QFD 관계 강도의 데이터 기반 보완
         → FMEA O(발생도)의 근거 보강
```

**확신도**: 90% -- Level 1(일별 집계) 분석으로 127일 x 3,691 피처 매트릭스가 이미 구축되어 있음.

#### 전략 C3: 변화점 빈도와 불량률 상관

CUSUM/EWMA 변화점 탐지 결과를 일별로 집계하여 불량률과의 상관을 분석합니다.

```
CUSUM/EWMA 변화점 탐지                    일별 불량 집계
(이미 실행 완료)                          (defect_selection_status)
       │                                        │
       ▼                                        ▼
  일별 변화점 빈도                          일별 불량률
  (태그별/구간별)                          (강종별)
       │                                        │
       └──────────┬─────────────────────────────┘
                  ▼
         Spearman 순위 상관 (rho)
         기대 결과: rho = 0.20~0.45
                  │
                  ▼
         "변화점이 많은 날 = 불량이 많은 날"
         → FMEA O(발생도)의 간접 근거
         → 기존 인프라 활용도 입증
```

## 3.2 Fisher's Exact Test (통계적 유의성 검증)

### 3.2.1 방법론 설명

Fisher's Exact Test는 소규모 표본에서 두 이진(binary) 변수 간 독립성을 검정하는 비모수적 방법이다. 본 분석에서는 **태그 이상치 발생 여부**와 **결함일 발생 여부** 간의 연관성을 검증하기 위해 적용한다.

**2x2 분할표(Contingency Table) 구성:**

|  | 결함일 (Defect=Yes) | 정상일 (Defect=No) | 합계 |
|--|:---:|:---:|:---:|
| **태그 이상 (Anomaly=Yes)** | a | b | a+b |
| **태그 정상 (Anomaly=No)** | c | d | c+d |
| **합계** | a+c | b+d | N |

- **귀무가설 (H0)**: 태그 이상치 발생과 결함일 발생은 독립적이다 (연관 없음)
- **대립가설 (H1)**: 태그 이상치 발생과 결함일 발생은 독립적이지 않다 (연관 있음)
- **유의 수준**: alpha = 0.05
- **검정 방법**: Fisher's exact test (양측 검정, 소표본 적합)

**Fisher 검정을 선택한 근거:**
- 결함일 데이터가 413일 중 83건(20.1%)으로 기대빈도가 5 미만인 셀이 발생할 수 있음
- chi-square 근사보다 정확한 p-value 산출이 가능
- 표본 크기 제약이 있는 산업 데이터에 적합

### 3.2.2 적용 가능 범위

현업 확인 47개 PLC 태그 중 Fisher 검정 적용 가능성을 분류한다.

| 구분 | 태그 수 | Fisher 검정 | 사유 |

### 3.2.4 Fisher 검정 실행의 제약과 해석 주의점

**데이터 해상도 한계 (L1):**
- 불량 데이터가 **일별 집계** 수준 → 코일 단위 매칭 불가
- Fisher 검정의 분할표가 "일" 단위로 구성되므로, 해당일 **전체**의 태그 이상 여부와 불량 발생 여부를 대응시키는 구조
- 이는 인과 방향의 해석에 한계를 야기 (동일 날 다른 코일의 이상이 결함과 무관할 수 있음)

**클래스 불균형 (L7):**
- 불량률=0인 날이 다수 → 분할표에서 (Anomaly=Yes, Defect=No) 셀이 과대 추정될 수 있음
- Odds Ratio 해석 시 이 점을 감안해야 함

**의미:**
> "현업이 직감으로 알고 있는 것을 데이터가 확인" — Fisher 검정은 이 명제를 통계적으로 뒷받침하는 도구이다. 그러나 현재 데이터 해상도 한계(일별 집계)로 인해, 검정 결과는 "방향성 확인" 수준이며, 코일 단위 추적 시스템(D1) 구축 후에야 정밀한 통계적 인과 검증이 가능하다.

### 3.4.3 현재 분석 중인 토크 태그와의 비교 프레임

Type C 태그의 잠재 가치를 평가하기 위해, 현재 분석 중이며 SHAP Top 3를 차지하는 동일 드라이브(PR6/PR7)의 토크 태그와 구조적 관계를 분석한다.

**동일 드라이브 내 태그 관계 (PR6L2 예시):**

```
PR6L2 드라이브 (PLC52)
├── ACT_TORQUE      [현재 분석 중, SHAP #1] ← 결과 지표 (출력)
├── ACT_SPD_MS      [현재 분석 중]           ← 결과 지표 (출력)
├── ACT_SPD_PERC    [Type C, 미분석]         ← 정규화된 속도 (% of rated)
├── ACT_CURR_PERC   [Type C, 미분석]         ← 전류 = 토크 비례 지표
├── ACT_POWER_PERC  [Type C, 미분석]         ← 전력 = 부하 종합 지표
├── REF_SPD_MS      [Type C, 미분석]         ← 설정값 (입력)
└── REF_TORQUE      [Type C, 미분석]         ← 설정값 (입력)
```

### 3.4.4 잠재 가치 평가 프레임워크

Type C 태그를 3개 진단 지표 그룹으로 구성하면, 현재 ACT_TORQUE/ACT_SPD만으로는 불가능한 심층 진단이 가능해진다.

#### 지표 그룹 1: 드라이브 건강도 지표 (Drive Health Indicator)

**구성**: SPD_PERC + CURR_PERC + POWER_PERC

| 파라미터 조합 | 진단 의미 | 이상 패턴 예시 |
|-------------|----------|-------------|
| SPD_PERC 정상 + CURR_PERC 상승 | 기계적 부하 증가 (마모, 정렬 불량) | 롤 마모 → 토크 상승 전 조기 감지 |
| POWER_PERC 급증 + SPD_PERC 하락 | 과부하 상태 (소재 끼임, 냉각 부족) | 핀치롤 정지 전조 |
| CURR_PERC 불안정 + POWER_PERC 정상 | 전기적 이상 (인버터 열화, 접촉 불량) | 드라이브 고장 전조 |

> **기대 효과**: 현재 토크만으로는 "이상이 있다"까지만 판단 가능. 전류/전력/속도% 추가 시 "왜 이상인가"(기계적 vs 전기적 vs 제어적)까지 진단 가능

#### 지표 그룹 2: 제어 성능 지표 (Control Performance Indicator)

**구성**: REF_SPD_MS vs ACT_SPD_MS 편차

| 편차 패턴 | 진단 의미 | 임계값 예시 |
|----------|----------|-----------|
| |REF - ACT| < 1% | 정상 추종 | 기준 상태 |
| |REF - ACT| = 1~5% | 제어 성능 저하 | 주의 관찰 |
| |REF - ACT| > 5% | 제어 이탈 | 즉시 점검 |
| REF 변동 없음 + ACT 변동 | 외란 유입 (소재 불균일, 온도 편차) | 품질 영향 가능 |

> **기대 효과**: 설정값(REF)과 실적값(ACT)의 편차는 **제어 루프의 건전성**을 직접 반영. 편차 증가 추세는 PID 튜닝 열화 또는 기계적 열화의 선행 지표

#### 지표 그룹 3: 부하 이상 지표 (Load Anomaly Indicator)

**구성**: REF_TORQUE vs ACT_TORQUE 편차

| 편차 패턴 | 진단 의미 | 품질 연관 |
|----------|----------|----------|
| ACT_TORQUE >> REF_TORQUE | 예상 이상의 부하 (소재 경도 이상, 온도 부족) | 직접 연관 |
| ACT_TORQUE << REF_TORQUE | 예상 미만의 부하 (소재 미진입, 공회전) | 생산 이상 |
| 양자 동시 급변 | 시스템 전환 (사이즈 변경, 강종 변경) | 정상 과도 구간 |

> **기대 효과**: SHAP #1인 PR6L2_ACT_TORQUE의 이상이 "설정값 자체의 문제"인지 "실적의 일탈"인지 구분 가능. 이는 대응 방향(설정 조정 vs 설비 점검)을 결정하는 핵심 정보

### 3.4.5 Type C 태그 분석 편입 시 기대 효과 종합

| 기대 효과 | 현재 상태 | Type C 편입 후 | 개선 폭 |
|----------|----------|-------------|:-------:|
| **이상 감지** | 토크/속도 이상 탐지 | + 전류/전력 이상 탐지 | 감지 범위 2x |
| **원인 진단** | "이상 발생" 수준 | "기계적/전기적/제어적" 원인 분류 | 진단 깊이 3x |
| **선행 지표** | 토크 급변 (사후) | 전류/전력 추세 변화 (사전) | 조기 감지 가능 |
| **제어 건전성** | 미모니터링 | REF-ACT 편차 추적 | 신규 영역 |
| **분석 태그 수** | 기존 ~12개 (PR 상세) | +30개 = ~42개 | +250% |

### 3.4.6 권장사항

1. **즉시 조치 (Phase 1)**: PR6~PR9의 Type C 태그 ~30개를 `tag_filter_config.yaml`의 `09b_PR_Detailed` 카테고리에 편입
   - 소요: config 파일 수정 + 분석 재실행 (코드 변경 최소)

2. **파생 지표 개발 (Phase 1.5)**: REF-ACT 편차 계산 로직 추가
   - SPD_DEVIATION = |REF_SPD_MS - ACT_SPD_MS| / REF_SPD_MS * 100
   - TORQUE_DEVIATION = |REF_TORQUE - ACT_TORQUE| / REF_TORQUE * 100
   - 편차의 이동평균 및 추세 분석 → 열화 조기 감지

3. **우선순위**: PR6L2 > PR6L1 > PR7L2 (SHAP 중요도 순)
   - SHAP Top 3 태그의 동일 드라이브 파라미터를 최우선 분석
   - 토크에서 이상이 감지된 드라이브의 전류/전력을 교차 확인하는 "드라이브 건강 대시보드" 구성

## 4.4 본 심층 분석의 한계 및 후속 과제

### 4.4.1 분석 방법론적 한계

| # | 한계 사항 | 영향 범위 | 심각도 | 완화 방안 |
|:-:|----------|----------|:------:|----------|
| H1 | **Jaccard/Kappa 산출의 측정 단위 이질성**: PLC(태그), 현업(측정 개념), AI(카테고리)를 "측정 개념"으로 통일했으나, 매핑의 주관성 존재 | §1 전체 | 보통 | 매핑 기준을 공개하고 대안 매핑으로 민감도 분석 수행 |
| H2 | **QFD 관계 강도의 주관적 판정**: 9/3/1 점수를 도메인 지식과 현업 경험에 기반하여 부여했으나, 코일 단위 데이터 검증 미수행 | §2.1 | 보통 | 코일 추적(C1) 도입 후 데이터 기반 강도 보정 |
| H3 | **FMEA O(발생도)의 불확실성**: 코일 단위 불량률을 산출할 수 없어 O값을 "?"로 표시한 항목 존재 | §2.2 | 높음 | Anomaly-First(B1) 결과로 간접 추정 후 보정 |
| H4 | **Fisher 검정 미실행**: 검정 조건 및 기대 결과만 제시, 실제 p-value 미산출 | §3.2 | 보통 | 즉시 실행 가능 (A4 조치 항목) |
| H5 | **Type C 태그 가치의 추론적 평가**: 실제 분석 결과 없이 구조적 관계에 기반한 잠재 가치 추정 | §3.4 | 낮음 | A1 조치(config 편입) 후 실증적 검증 |
